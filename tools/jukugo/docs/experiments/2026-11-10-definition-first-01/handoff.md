# Хэнд-офф: независимая проверка пути от толкования

## Задача и разрешение

Пользователь хочет добавить в репозиторий более простой, но надёжный начальный путь исследования состава японского слова. Разрешён следующий этап: короткий черновик правил и новые прогоны на трёх словах. Пользователь отдельно потребовал не смотреть готовые разборы. Этот запрет важнее обычных требований прочитать старый разбор/образец перед работой.

Тестовые формы в фиксированном порядке: **責任 → 上達 → 格好**. Это список объектов, не распределение по ожидаемым исходам. Для 格好 пользователь выбрал **かっこう**. Не назначать заранее ни одному слову роль «положительного», «сложного» или «ошибочного» примера. Значения, происхождение, состав и исходы предстоит установить заново.

Этот пакет предназначен для нового независимого случая. Не переносить переписку, контрольные точки других слов или готовые отчёты в новый чат. Для каждого слова — отдельный чат; исследовать только слово, указанное пользователем.

## Проверенная исходная среда

- Репозиторий: `bkarpenko/jp-tools` на GitHub, стартовый пакет в `main`; подойдёт чистый облачный клон. Пояс Europe/Moscow.
- На подготовку: ветка main; HEAD = origin/main = **1ad3d417ee3e3d0f7f2ee3769d0c258ae13488a7**.
- Blob основного PIPELINE.md: **fa0f35da06a7cc27441d496fe2496217630dbeda**.
- Входы принятого метода чистые: PIPELINE, references, examples, goshu.py, check_glosses.py, ru_pass.py, skill.json, shared/corpus.py, shared/data.
- Рабочая копия содержит чужие/предыдущие незакоммиченные исследования и изменения документации. Их не удалять и не переписывать. Текущее состояние повторно проверить git status --short --branch и git rev-parse HEAD; не выводить полный diff исследовательских файлов.
- Не переключать и не обновлять общую рабочую копию автоматически. Для передачи между устройствами действовать по `docs/research-handoff.md`. Правки принятой методики/сверщика требуют отдельной ветки от согласованной ревизии.

## Что читать в новом чате

1. AGENTS.md в корне: организационные требования, языки, сохранение, область разрешений.
2. Этот handoff.md, затем [protocol.md](protocol.md), [дополнение v2](protocol-v2-coverage.md), [access.md](access.md) и [state.md](state.md) рядом. Правила проверки охвата из v2 применяются к новым случаям; историческое описание первого применения не задаёт им ожидаемого результата.
3. neutral/PIPELINE.md — копия базовой процедуры без фрагментов о тестовых словах; experimental protocol.md явно задаёт изменённые шаги.
4. neutral/web-sources.md, neutral/SCHEMA.md, neutral/russian.md. Часть синтаксических примеров в реестре удалена; безопасная инструкция доступа — access.md.
5. README.md в корне и docs/workflow.md; их старые облачные требования отменены действующим AGENTS.md. Для остальных общих соглашений — neutral/CLAUDE.md и neutral/jukugo-README.md.
6. manifest.json: источник копий, blob/hash и границы удаления. Это происхождение материалов, не результаты слов.

Ссылки из обезличенных файлов **не отменяют** запреты ниже. Не переходить по ним автоматически. Удалённые фрагменты не восстанавливать из Git, установленных скиллов или других копий.

## Что не открывать до независимой фиксации результатов

- Готовые разборы, state/report/brief/sources и сохранённые доказательства всех трёх тестовых слов, где бы они ни находились.
- tools/jukugo/examples/ целиком: там есть готовый разбор одного из объектов.
- tools/jukugo/docs/deferred/analyses/ и docs/_archive/: готовые случаи и история выводов.
- tools/jukugo/docs/analyses/README.md глазами: таблица содержит прежние результаты. Список имён каталогов можно использовать только для выбора свободного ID; содержимое старых каталогов не читать.
- tools/jukugo/docs/open-questions.md и docs/decisions.md, оригинальные PIPELINE.md, tools/jukugo/README.md, CLAUDE.md и references/web-sources.md: они содержат подсказки о тестовых словах. Вместо нужных инструкций использовать подготовленные neutral/ и protocol.md.
- Историю прежнего чата, поиск по старым чатам/памяти, готовые выводы в Git diff/log/show, установленные копии скилла, dist, старые отчёты в любом другом месте.
- Размеченный список примеров examples_normalized.tsv как подсказку для выбора типа до собственного вывода.

Безопасны код корпусного шага, его таблицы, код сверщика, ru_pass.py, манифест, текущие собственные записи **нового** испытания и источники, заново открытые для него. Новые словарные статьи могут совпасть с ранее использованными — это допустимо: они добываются заново, прежние выписки не используются.

Общий указатель исследований после создания новой пары обновлять скриптом без вывода прежних строк: чтение для сохранения неизменённых байтов допустимо, использование их содержания как исследовательской подсказки запрещено. Свои результаты можно отдельно индексировать в этом экспериментальном каталоге. Не выполнять глобальный rg по docs с тестовыми словами: это вскроет прежние ответы.

## Как устроено независимое испытание

Независимость здесь означает отсутствие доступа к прежним выводам и фиксацию правил до доказательств, а не обещание отсутствия у модели любых фоновых знаний. Ссылаться только на полученные источники; знания по памяти не превращать в свидетельства.

До первого внешнего запроса новый чат читает protocol.md и фиксирует его выбранную редакцию/hash. Затем идёт по одинаковому порядку для всех слов. Нельзя менять критерии, чтобы получить удобный итог. Если правило оказалось недостаточным, записать наблюдение; правку применять только с явной новой версией и указанием, какие случаи требуют повторной проверки.

Сначала зафиксировать собственный результат одного слова, основания и открытое, затем переходить к следующему. Оставить датированную копию собственного результата и SHA-256 в журнале. Не менять уже зафиксированный ответ без истории пересмотра. Старые разборы не использовать для сверки даже после окончания серии без отдельного разрешения пользователя.

## Сохранение и выход

- Для каждой определённой пары форма/значение — новый свободный каталог по AGENTS.md, не перезапись прежнего. До определения пары вести подготовку в этом экспериментальном каталоге.
- С начала каждого случая: state.md, sources.md и частичный report.md; обновлять после значимых источников/выводов. Краткое объяснение можно сохранить отдельным brief.md.
- Сохранять полный SHA базового метода, blob PIPELINE и SHA-256 `protocol.md` и `protocol-v2-coverage.md`. Новую процедуру называть предварительной, не принятой версией коммита.
- В sources.md: время с поясом, издание, точный запрос и охват, фактически открытый URL, результат и очищенная выписка. Старые материалы не копировать. Данные авторизации не сохранять.
- Частичные результаты не объявлять завершёнными по действующей процедуре. Формальные ошибки старого сверщика не закрывать выдуманной формулой; отделять ошибки согласованности переводов от требований пропущенных стадий.
- После серии: короткая сравнительная таблица, что удалось объяснить, какие проверки потребовались и где путь не дал достаточного результата. Не измерять успех совпадением с прежним ответом; не утверждать выигрыш во времени без сопоставимого замера.
- Лишь после независимых прогонов готовить изменение принятой процедуры в отдельной ветке. Само согласие проверить маршрут не разрешает commit/push/merge/install. Пакет скилла на этом этапе не собирать.

## Подача пользователю

Пользователь не профессиональный лингвист и не должен читать отчёт для понимания ответа. Дать происхождение слова с основанием, старшее и рассматриваемое современное значения, короткие цитаты, понятную связь частей и переход, затем конкретные сомнения. Объяснения по-русски; переводы слов/примеров для пользователя по-английски; оригиналы сохраняются. Подробный отчёт — проверочное приложение. Коды стадий, логи, счётчики и длинные методические оговорки не переносить в ответ без запроса.
