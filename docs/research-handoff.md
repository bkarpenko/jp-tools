# Продолжение исследований с другого устройства

1. **Перед запуском нового исследования.** Для обычного разбора используй `AGENTS.md` и принятую ревизию метода на GitHub. Для независимого испытания сначала опубликуй в `main` стартовый пакет: точку входа, протокол и дополнения, версии, порядок доступа и нейтральные материалы. Не включай в пакет результаты тестовых слов. Дай ссылку на файл входа и SHA публикации.
2. **Перед передачей начатого разбора.** Сохрани пару (форма, чтение, значение), ревизию метода, выводы и их ограничения, источники с локаторами, следующий конкретный шаг. Для независимой серии контрольную точку каждого слова публикуй отдельно, в его ветке `codex/<слово>-<дата>`. На запрос «продолжу с другого устройства» публикуй контрольную точку и проверяй её на GitHub в рамках этого запроса. Остальные локальные изменения оставь на месте. Полные выписки из источников с ограниченным доступом и данные входа в публичный репозиторий не переносятся; используй краткие выдержки, пересказ и точные ссылки. Для переноса полных рабочих материалов заранее согласуй закрытое хранилище.
3. **Проверь передачу.** Сверь SHA удалённой ветки и наличие файлов по выданной ссылке. Проверь, что файлы и версии из стартовой инструкции есть в чистой копии. До проверки говори «сохранено локально», после — «доступно с другого устройства». В ответе дай путь, ветку и короткую команду для нового чата. Для одного разбора одновременно работает один чат.

В новом облачном чате открой именно `bkarpenko/jp-tools` и указанную ветку. Для нового независимого слова начни со стартового пакета в `main`. Для продолжения конкретного слова начни с `state.md` его контрольной точки и указанной там версии метода. Если старый чат уже открывал результаты слова, начни независимую проверку в отдельном чате.

Проверка GitHub не проверяет подписки на словари. При первом входе из облачной сессии проверь наличие внутреннего браузера и доступ отдельно. Если прежняя авторизация не перенеслась, зафиксируй недоступный источник, используй доступные разрешённые материалы и укажи, что нужно открыть повторно. Не подменяй словарь и не считай отказ доступа отсутствием статьи.
