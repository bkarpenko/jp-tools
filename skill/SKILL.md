# jp-freq — частотная справка по BCCWJ

Источник: https://github.com/bkarpenko/jp-freq — там код, данные и дока.
Этот пакет самодостаточен: всё нужное лежит рядом с этим файлом, в сеть ходить
не надо. Если нужна свежая версия — пересобрать пакет из репозитория.

## Что это отвечает

Один вопрос: **насколько этот кандзи или слово реально употребляется** — с вердиктом,
частотой, рангом и шкалой, на которой ранг что-то значит.

Значениями, переводами, разбором компонентов, мнемоникой и этимологией скилл
**не занимается**. Если спрашивают об этом — сказать прямо, что это другой инструмент,
и не выводить значения из частотных данных.

## Как запускать

Рядом с этим файлом лежат `freq.py` и папка `data/`. Зависимостей нет — только
стандартная библиотека Python 3.

```
python freq.py 浸              один знак -> справка по кандзи
python freq.py 浸かる           слово     -> справка по слову
python freq.py 扉 唾 引き戸     список    -> сравнительная таблица
python freq.py --html 浸かる    то же самое страницей в out/
python freq.py --check         проверка целостности данных
```

Развилку скрипт делает сам: один иероглиф → трек «кандзи», одно слово → трек «слово»,
два аргумента и больше → сравнительная таблица. Переспрашивать не надо.

Ответ приходит за 1–3 секунды на запрос; на список из десяти слов — до полуминуты.

## Где искать файлы, если рядом их нет

1. Рядом с этим SKILL.md (обычный случай — скилл несёт данные с собой).
2. Подключённая папка проекта `jp-freq`, если сессия привязана к компьютеру.
3. Ни там, ни там — **сказать честно, что данных нет, и остановиться**. Числа по
   памяти не выдавать ни при каких обстоятельствах: весь смысл в том, что они
   из BCCWJ, а не из головы модели. Проверка наличия — `python freq.py --check`.

## Как отдавать результат

- Если файл можно отдать пользователю — запускать `--html` и **отдавать страницу
  файлом**. Причина: колонки, выровненные пробелами, в японском тексте не держатся —
  знак занимает два знакоместа, и таблица разъезжается в чате и на телефоне.
- Если файл отдать нельзя — текстовый режим, и **вывод вставлять в ответ целиком**:
  сам по себе вывод скрипта до пользователя не доходит.
- **Не пересказывать вывод своими словами, не переоформлять его в таблицы,
  не дописывать интерпретацию.** Вердикт, шкалы и выводы под блоками скрипт печатает
  сам; пользователь читает выгрузку напрямую.
- Комментарий уместен только там, где в данных видно неочевидное: расхождение SUW
  и LUW2, перекос по жанрам, ловушка с записью каной, слово на границе полосы.

## Если запрос не нашёлся

Скрипт сам предложит леммы, которым принадлежит это написание, — запустить повторно
по предложенной лемме, **не спрашивая разрешения**. Леммы в BCCWJ даны в нормализации
UniDic, и запрос часто не совпадает с ней: `ちょっと` → `一寸`, `ついに` → `遂に`,
`引き換える` → `引き替える`.

Если и по написанию ничего нет, сказать это прямо и предложить проверить чтение —
подставлять похожее слово от себя нельзя.

## Что означают величины

- **pmw** — вхождений на миллион единиц корпуса. Сам по себе непрозрачен, поэтому
  наверх всегда выносится «раз на столько-то слов (символов)» = 10⁶ / pmw.
- **Ранг** — место в частотном списке. У кандзи он считается от рабочего списка
  (2499 знаков, 99,5 % всех вхождений), а не от всех 6940: хвост — имена собственные,
  цитаты и разовые написания.
- **Кумулятивное покрытие** — сколько текста закрывают все единицы до этой.
- **Слово или морфема** — баланс вхождений: сколько процентов единица стоит
  отдельным словом, а сколько уходит внутрь более длинных слов. Обе доли из одной
  таблицы (`suw`), поэтому сумма всегда ровно 100 %. Список составных под балансом
  идёт из `luw2` — другая разметка, и насколько он баланс покрывает, на карточке
  сказано отдельной строкой.
- **Доля записи знаком** — слово может быть частотным, а знак в нём почти невидимым
  (遂に: 14 % вхождений знаком, остальное каной).

Четыре разных знаменателя, путать их нельзя: pmw кандзи считается от всех символов
корпуса, кумулятивная доля кандзи — от всех вхождений кандзи, pmw слов LUW2 и SUW —
от своих наборов токенов. Величины с разными знаменателями рядом не ставить.

## Как обновляется этот скилл

Правки идут **в репозиторий**, не в установленную копию: установленная — артефакт
сборки, и следующая сборка её перезапишет.

1. Поправить в клоне репозитория (`skill/SKILL.md`, `freq.py`, при пересборке
   корпуса — `data/`), закоммитить и запушить.
2. `python build_skill.py` → `dist/jp-freq-skill.zip` (данные `.gz`, ~23 МБ;
   `--xz` — тот же пакет на ~16 МБ, если не проходит лимит загрузки).
3. Загрузить zip заново в настройки Claude — это делает Борис руками.

Правки только в `README.md`, `CLAUDE.md` или `docs/` перезаливки не требуют:
в пакет эти файлы не входят.

## Чего не делать

- Не отвечать по памяти и не «уточнять» числа скрипта.
- Не править файлы в `data/` — они выведены из корпуса и правке не подлежат.
- Не строить парадигму глагола по данным: в таблице написаний лежат варианты
  **записи**, а не формы спряжения.
